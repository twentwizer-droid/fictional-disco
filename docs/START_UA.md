# bundlehunter: інструкція для запуску

Бот працює 24/7 на сервері, а ти керуєш ним із Telegram і дивишся все у веб-панелі.
Програмувати не треба: потрібно лише скопіювати кілька команд.

> **Важливо.** За замовчуванням бот торгує **на папері**, без реальних грошей. На реальні гроші
> він перейде лише тоді, коли ти зробиш це сам (розділ «Реальні гроші»). Більшість угод з
> мемкоїнами збиткові. Спершу кілька днів подивись, як бот торгує на папері.

## Що він уміє

- **Записує кожен запуск на pump.fun.** Через 30 хвилин аналізує ті, де був бандл: хто
  бандлив, хто його профінансував, скільки заробив.
- **Знаходить групи бандлерів «в плюсі»** і копіює їх. Купує на просадках, а не на хаях, і
  продає, коли група починає продавати.
- **Перевіряє токени**, як LarpCheck і Axiom: чи справжній наратив, чи немає скопійованих
  соцмереж і позиченого сайту, скільки тримають бандлери, інсайдери й снайпери.
- **Аналізує наратив:** знаходить усі токени під нього й показує оригінал, копії та LARP.
- **Пише в Telegram**, коли купує чи продає, і коли з'являється новий токен під твій наратив.
- **Сигнал-бот:** додаєш плюсових трейдерів, і бот пише про кожну їхню купівлю разом з аналізом бандла.

## Що знадобиться

1. **Сервер (VPS)** з Ubuntu 22.04 або 24.04, від 2 ГБ пам'яті. Найкраще в дата-центрі у
   Франкфурті або Амстердамі, бо там поруч Jito і це швидше. Підійде Hetzner, DigitalOcean,
   Vultr чи інший; це приблизно 5–10 $ на місяць.
   Можна й на своєму комп'ютері (Linux чи macOS), але тоді він має бути постійно ввімкнений.
2. **Ключ Solana RPC.** Зареєструйся на <https://helius.dev> і скопіюй з кабінету адресу
   вигляду `https://mainnet.helius-rpc.com/?api-key=...`. Безкоштовного тарифу вистачить,
   щоб спробувати. Для постійної роботи краще платний.
3. **Telegram-бот.** Створи його за 1 хвилину (крок 2).

## Крок 1. Підключись до сервера

У Windows відкрий PowerShell, у macOS — «Термінал». Впиши (IP і пароль тобі
надішле хостинг):

```bash
ssh root@IP_СЕРВЕРА
```

## Крок 2. Створи Telegram-бота

1. У Telegram знайди **@BotFather** і напиши `/newbot`.
2. Придумай назву й ім'я, що закінчується на `bot` (наприклад `my_bundle_hunter_bot`).
3. BotFather надішле **токен** вигляду `123456789:AA...`. Збережи його, він знадобиться на кроці 4.

## Крок 3. Встанови Docker і завантаж проект

На сервері по черзі:

```bash
curl -fsSL https://get.docker.com | sh
apt-get install -y git
git clone -b claude/solana-memecoin-bundle-analyzer-ycad4o https://github.com/twentwizer-droid/fictional-disco.git bundlehunter
cd bundlehunter
./install.sh --docker
```

- Якщо репозиторій приватний, `git clone` попросить логін GitHub і пароль. Замість пароля
  потрібен *personal access token* (GitHub → Settings → Developer settings → Tokens).
- Коли pull request змерджено в основну гілку, `-b claude/...` можна прибрати.

`install.sh` створить файли налаштувань і **пароль для веб-панелі**. Він покаже його на
екрані й збереже у файлі `.env`.

## Крок 4. Впиши ключі

```bash
nano .env
```

Заповни два рядки:

```
BH_RPC_URL=https://mainnet.helius-rpc.com/?api-key=ТВІЙ_КЛЮЧ
BH_TELEGRAM_TOKEN=123456789:AA...
```

Збережи: `Ctrl+O`, `Enter`, потім вийди: `Ctrl+X`.

Якщо в тебе безкоштовний тариф Helius, зменш швидкість запитів: `nano config.toml` і в розділі
`[rpc]` постав `requests_per_second = 4`.

## Крок 5. Запусти

```bash
docker compose up -d --build
```

Перший запуск триває кілька хвилин. Подивитися, що робить бот (вихід: `Ctrl+C`, бот при цьому
працює далі):

```bash
docker compose logs -f
```

## Крок 6. Дай собі доступ до бота

1. Відкрий свого бота в Telegram і натисни **Start** (`/start`).
2. Бот відповість: «Доступ закритий. Твій ID: 123456789». Так і має бути: чужим він не відповідає.
3. Впиши цей ID у `.env` (`nano .env`):
   ```
   BH_TELEGRAM_ALLOWED_IDS=123456789
   ```
4. Перезапусти: `docker compose up -d`
5. Знову напиши боту `/start`, і він покаже меню.

## Крок 7. Відкрий веб-панель

Панель відкрита лише на самому сервері, щоб ніхто сторонній її не бачив. Відкрий її на своєму
комп'ютері через SSH-тунель, в окремому вікні термінала:

```bash
ssh -L 8080:localhost:8080 root@IP_СЕРВЕРА
```

Поки це вікно відкрите, заходь у браузері на **http://localhost:8080**. Логін будь-який,
пароль — з `.env` (подивитися на сервері: `grep BH_WEB_PASSWORD .env`).

У панелі є вкладки:
- **Огляд** — стан бота, скільки запусків записано, групи, PnL, відкриті позиції;
- **Перевірка токена** — вставляєш адресу й отримуєш LARP-перевірку та холдерів, як на Axiom;
- **Наратив** — пишеш наратив і бачиш усі токени під нього: оригінал, копії, бандли;
- **Групи бандлерів** — хто в плюсі, їхні гаманці й токени;
- **Угоди** — що бот купив і продав.

## Команди в Telegram

| Команда | Що робить |
|---|---|
| `/check <адреса>` | LARP-перевірка + холдери (Top 10, Dev, Snipers, Insiders, Bundlers) |
| `/narrative <наратив>` | усі токени наратива: оригінал, копії, LARP, бандли, вибір |
| `/watch <наратив>` | повідомляти про кожен новий токен під цей наратив |
| `/unwatch` | зупинити стеження |
| `/clusters` | групи бандлерів «в плюсі» |
| `/cluster <група або гаманець>` | деталі групи: гаманці, токени, коли й з ким |
| `/positions` | угоди бота |
| `/status` | стан бота |
| `/addtrader <гаманець> [назва]` | додати трейдера: сигнал на кожну його купівлю |
| `/traders` | твої трейдери з PnL |
| `/trader <гаманець>` | перевірити будь-який гаманець: чи він у плюсі |
| `/deltrader <гаманець>` | прибрати трейдера |
| `/rank` | завантажити історію і відсортувати трейдерів за реальним PnL |
| `/scalp` | скальпінг: стан, що чекає підтвердження, які угоди пропущено і чому |

Можна просто надіслати адресу токена (буде `/check`) або слова наратива (буде `/narrative`).
Наратив можна задати словами (`trump cat`), посиланням на твіт чи сайт, або адресою токена.

## Сигнал-бот: твої трейдери + бандли

Знаходиш плюсові гаманці трейдерів (GMGN, Axiom, Cielo, власні пошуки) і додаєш їх у бота:

```
/addtrader 7xKp...гаманець Alpha
```

Бот завантажить історію угод цього гаманця й порахує його **справжній PnL**: скільки вклав,
скільки вивів, відсоток угод у плюс. Так одразу видно, чи гаманець справді плюсовий, чи це
показуха. Перевірити гаманець, не додаючи його: `/trader <гаманець>`.

Після цього бот пише тобі в Telegram:

| Сигнал | Коли |
|---|---|
| 📡 **Трейдер купив** | твій трейдер купив токен (від 0.2 SOL, налаштовується) |
| 🔥 **2–3 твоїх трейдери в одному токені** | кілька твоїх трейдерів купили той самий токен за 30 хв: найсильніший сигнал |
| 🔻 **Трейдер продає** | трейдер продає токен, про який був сигнал: час подумати про вихід |
| 📦 **Прибуткова бандл-група зайшла в токен** | група бандлерів «в плюсі» запустила чи купила токен; бот покаже, чи там уже твої трейдери |
| 🔎 **Аналіз** | одразу після сигналу: скільки тримають бандлери, інсайдери, снайпери, топ-10, хто розробник і LARP-оцінка з червоними прапорцями |

**Багато гаманців одразу.** Експорт з Axiom чи GMGN (файл `.txt` / `.json`) просто надішли
боту в Telegram як файл. Бот:
- прибере дублікати;
- розсортує гаманці за назвами: плюсові (pnl, %, «+» у назві), трейдери, без назви,
  бандл-групи, розробники, снайпери, інсайдери, позначені як погані, біржі;
- додасть у стеження лише перші три категорії.

Потім напиши `/rank`. Бот завантажить історію гаманців (по 30 за раз, плюсові першими) і
відсортує їх за **реальним** PnL. Гаманці з однаковою назвою (одна людина з багатьма
гаманцями) рахуються як один трейдер.

На комп'ютері те саме: `bh trader import файл1 файл2 --csv відсортовано.csv`, потім `bh trader rank`.

Список трейдерів із PnL: `/traders` у Telegram або вкладка «Трейдери» у веб-панелі.
Прибрати: `/deltrader <гаманець>`.

Налаштування (у `config.toml`, розділ `[signals]`): мінімальна сума купівлі для сигналу,
вікно для кількох трейдерів, чи присилати продажі й аналіз.

Сигнали — це лише повідомлення, бот за трейдерами не купує. Перед входом дивись на аналіз:
якщо там важкий бандл чи червоні прапорці, трейдер може бути вихідною ліквідністю так само,
як і ти.

## Глибокий аналіз гаманців

Для кожного твого трейдера бот рахує з реальних угод (вкладка «Трейдери», `/trader`, `/traders`):

- **Score 0–100.** 40% — відсоток угод у плюс, 30% — profit factor, 20% — PnL, 10% — кількість
  угод. Менше 5 закритих угод — «мало даних».
- **Стиль** за тим, скільки він тримає позицію:
  - бот / снайпер (менше хвилини) — за ним не встигнеш;
  - скальпер (до 10 хв);
  - інтрадей;
  - холдер.
- **Profit factor:** сума виграшів / сума програшів. Більше 1.5 — реальна перевага, менше 1 —
  втрачає гроші.
- Середній виграш і програш, середній ROI, найкраща й найгірша угода, угод на день.

## Скальпінг (друга стратегія)

Бот бере частину руху (20–60%) у токенах, куди зайшли твої сильні трейдери, і виходить.
Кожне правило скальпінгу — це перевірка в коді:

| Правило | Як бот його виконує |
|---|---|
| Не входь без причини | купує лише якщо зайшов твій трейдер зі score від 80, або хоча б 2 різні трейдери зі score від 60 |
| Не купуй рух наосліп | потрібне підтвердження за останню хвилину: від 3 SOL купівель, купівлі переважають продажі у 1.5 раза, від 5 різних покупців |
| | не входить у «вертикальну свічку» (+25% за 15 с) і не доганяє: не дорожче ніж +50% від входу сильних |
| | перевіряє холдерів (бандлери, інсайдери) і LARP-оцінку |
| Завжди май план | до входу задає тейк-профіт (до +60% для малої позиції, до +20% для великої), стоп −15%, трейлінг 10% після половини тейку, максимум 10 хв |
| Умій вчасно вийти | виходить, коли продажі переважають купівлі або сильні гаманці продають — навіть до стопу |
| Не мсти ринку | після збитку 10 хв пауза; після 3 збитків поспіль — година паузи; денний ліміт збитку; не більше 6 угод на годину |
| Умій не входити | не підтвердилось за 5 хв — пропускає і записує чому (вкладка «Огляд» → «Скальпінг», `/scalp`) |

Кожна угода зберігає **чому** бот увійшов і **план**, а вихід — **чому** вийшов. Це видно
у вкладці «Угоди» і в повідомленнях Telegram. Усі пороги налаштовуються в розділі `[scalp]`
у `config.toml`. Торгує на папері, поки ти сам не ввімкнеш live (розділ «Реальні гроші»).

Важливо: скальпінг працює лише тоді, коли трейдери мають score. Тому спершу `/rank`.

## Скільки чекати результатів

Групи «в плюсі» з'являться не одразу. Бот має записати запуски, дочекатися, поки бандли
продадуть, і проаналізувати їх. Зазвичай це від кількох годин до 1–2 днів. Щоб пришвидшити,
дай йому гаманці бандлерів, які ти вже знаєш (з GMGN, Bubblemaps тощо):

```bash
docker compose exec bot bh seed АДРЕСА_ГАМАНЦЯ
```

## Реальні гроші

Роби це лише після кількох днів торгівлі на папері (`/positions`, вкладка «Угоди»).

1. Створи **окремий новий гаманець** (наприклад у Phantom) і поклади туди лише ту суму, яку
   готовий втратити. Основний гаманець ніколи не використовуй.
2. Експортуй приватний ключ цього гаманця (Phantom: налаштування → гаманець → «Показати
   приватний ключ»).
3. У `.env` додай:
   ```
   BH_PRIVATE_KEY=твій_приватний_ключ
   BH_LIVE_TRADING=1
   ```
4. У `config.toml` перевір розмір угоди: `buy_sol = 0.05` (стільки SOL на одну купівлю) і
   `daily_loss_limit_sol` (після такого збитку за день бот перестає купувати).
5. У `docker-compose.yml` зміни рядок `command: ["serve"]` на `command: ["serve", "--live"]`.
6. Перезапусти: `docker compose up -d`. У Telegram `/status` має показати «LIVE».

Повернутися на папір: прибери `--live` і перезапусти. Зупинити все: `docker compose down`.

## Оновлення

```bash
cd bundlehunter
git pull
docker compose up -d --build
```

Дані (база запусків, груп, угод) лежать у папці `data` і при оновленні не зникають.

## Без Docker (на своєму комп'ютері, Linux або macOS)

```bash
./install.sh      # один раз
nano .env         # впиши BH_RPC_URL і BH_TELEGRAM_TOKEN
./start.sh        # запуск; зупинка: Ctrl+C
```

Панель: <http://localhost:8080> (на своєму комп'ютері пароль не питає).

## Якщо щось не працює

| Що бачиш | Що зробити |
|---|---|
| Бот у Telegram мовчить | `docker compose logs -f`: перевір, чи правильний `BH_TELEGRAM_TOKEN` |
| «Доступ закритий» | впиши свій ID у `BH_TELEGRAM_ALLOWED_IDS` і перезапусти (крок 6) |
| Панель не відкривається | чи відкрите вікно з `ssh -L ...` (крок 7) і чи працює бот (`docker compose ps`) |
| `set BH_WEB_PASSWORD` у логах | впиши будь-який пароль у `BH_WEB_PASSWORD=` в `.env` і перезапусти |
| Помилки `429` / `rate limit` | RPC не встигає: зменш `requests_per_second` у `config.toml` або візьми платний тариф |
| `refusing to trade live` | для реальних грошей потрібні і `--live`, і `BH_LIVE_TRADING=1` |
| Порожньо в «Групах бандлерів» | бот ще збирає дані; зачекай або додай гаманці через `bh seed` |
